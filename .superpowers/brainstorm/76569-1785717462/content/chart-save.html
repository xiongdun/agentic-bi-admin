① 图表保存 · 设计方案

把会话/工作台里的临时图表变成可复用资产

核心问题

当前图表只存在于 BiChatMessage.sql_result 里，会话结束就找不到了。用户没法把"上次问的那个销售趋势图"再次打开、分享给同事、或组装到仪表盘。

数据模型
BiChart (新建)
├─ id, tenant_id, created_by (AuditMixin)
├─ name 图表标题
├─ description 图表说明
├─ datasource_id 数据源
├─ chart_type bar/line/pie...
├─ x_col, y_col XY 字段
├─ sql_text 来源 SQL
├─ sql_result_json 结果快照 JSON
├─ tags 标签（逗号分隔）
├─ is_public 是否公开
└─ share_token 外部分享 token

复用 BiChatSqlResult 结构存结果快照，刷新时按 sql_text 重跑

关键交互
① 保存入口
智能对话/SQL 工作台的图表右上角加"保存为图表"按钮
② 图表列表页
新增 /bi/charts 页面：卡片网格、搜索、按标签筛选
③ 刷新数据
打开图表 → 点"刷新" → 重跑 sql_text → 更新结果
④ 分享
生成 share_token → /bi/share/{token} 只读页（无需登录）

关键设计决策（需你确认）

设计倾向

  • 结果快照 vs 只存 SQL：倾向两者都存。SQL 用于刷新，快照用于离线查看（数据源不可用时不影响看图）
  • 分享 token：用 sqid 编码（项目已有），32 位长度，不可猜测
  • 权限：保存的图表走 RBAC（按钮码 B_BI_CHART_*），公开分享页走 token 校验

风险/限制

  • 结果快照可能很大（万行数据）→ 限制保存时最多 1000 行
  • SQL 可能引用已删除的表 → 刷新失败时显示快照 + 警告
  • 分享页暴露数据 → 默认 is_public=false，需用户主动开启
