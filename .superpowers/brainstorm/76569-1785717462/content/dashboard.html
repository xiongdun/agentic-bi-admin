③ Dashboard 仪表盘 · 设计方案

把已保存的图表组装成可布局、可分享的数据看板

核心问题

当前用户只能一条一条问数据，无法把"销售趋势 + 区域分布 + TOP10 客户"放在一个页面上对比查看。企业 BI 的核心场景是"打开看板就知道全局状况"，没有 Dashboard 就只是取数工具，不是 BI 平台。

数据模型
BiDashboard (新建)
├─ id, tenant_id, created_by
├─ name 看板标题
├─ description 看板说明
├─ layout_json 布局配置
├─ filters_json 全局筛选器
├─ refresh_mode manual/auto
├─ refresh_interval 自动刷新秒数
├─ is_public, share_token
└─ AuditMixin + SoftDeleteMixin
BiDashboardChart (新建，关联表)
├─ id, dashboard_id, chart_id
├─ position_x, position_y
├─ width, height 栅格单位
└─ override_config 覆盖图表配置
（同一图表可加入多个看板，位置独立）
页面结构
看板列表页 /bi/dashboards
卡片网格，显示名称/图表数/最后刷新时间
支持搜索、按标签筛选、新建
看板查看页 /bi/dashboards/{id}
栅格布局展示所有图表
顶部全局筛选器（可选）
右上角：刷新/编辑/分享/全屏
看板编辑页 /bi/dashboards/{id}/edit
左侧：已保存图表列表（拖入）
中间：栅格画布（拖拽/调整大小）
右侧：选中图表的属性面板
分享页 /bi/dashboard/share/{token}
只读看板，无需登录
复用图表保存的 token 机制

布局方案对比

固定栅格（推荐）

12 列栅格，图表占 N 列 M 行。用 vue-grid-layout 组件。简单稳定，满足绝大多数看板场景

自由画布

绝对定位，任意位置/大小。灵活但复杂，图表易重叠，移动端适配难

关键设计决策（需你确认）

设计倾向

  • 布局引擎：用 vue-grid-layout（Vue3 版），12 列栅格，支持拖拽 + 调整大小 + 响应式。项目已用 Naive UI，组件兼容性好
  • 图表数据刷新：打开看板时并行刷新所有图表（Promise.all），单个图表失败不影响其他。支持手动刷新 + 可选自动刷新（refresh_mode=auto, refresh_interval=300s）
  • 全局筛选器：filters_json 存键值对（如 {"date_range": "last_30d"}），刷新图表时把筛选值注入 SQL 的占位符。一期只支持日期范围，后续扩展
  • 权限：看板走 RBAC（B_BI_DASHBOARD_*），分享页走 token。看板内图表不单独鉴权（能看看板就能看里面的图表）
  • 与图表保存的关系：看板只引用 chart_id，不复制图表数据。图表被删除时看板显示"图表已删除"占位

风险/限制

  • 多图表并行刷新可能压垮数据源 → 限制并发数（最多 5 个并行，其余排队）
  • vue-grid-layout 是新依赖 → 需评估包大小和兼容性
  • 全局筛选器只支持日期范围（一期），复杂筛选后续迭代
  • 看板分享页不展示敏感图表（chart.is_public=false 的不参与分享）
